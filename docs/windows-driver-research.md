# ScanSnap SV600: результаты исследования Windows-драйвера

Дата фиксации: 28 августа 2026 года.

## Итоговая модель устройства

SV600 состоит из двух независимых USB-устройств:

| USB ID | Устройство | Назначение |
|---|---|---|
| `04c5:128e` | ScanSnap SV600 | линейный CCD/LED, механический проход и полноразмерный RGB |
| `04c5:13ba` | USB Camera | UVC 640×480: AGC, движение, отражения и page-turn |

Высококачественный скан приходит не с UVC-камеры. Камера не нужна для обычного
ручного запуска плоского скана; книжный и page-turn workflow в проект не входят.

Оригинальная Windows-цепочка не является TWAIN/ISIS-драйвером. PFU использует
STI user-mode minidriver `SV600u-x64.dll`, затем собственные controller и image
processing DLL ScanSnap Manager/Home. Упрощённая цепочка:

```text
CCD/LED scanner
  -> vendor USB protocol
  -> SV600u-x64.dll
       -> shading/LUT
       -> dense per-line, per-channel R/G/B optical remap
       -> interpolation and requested scale
  -> ScanSnap image processing
       -> fixed crop or document detection
       -> deskew/perspective/crop/rotation
  -> JPEG/PDF/UI
```

## Что приходит из прошивки

При полном поле и 300 dpi Linux получает RGB8 около `5104×3542`. Это ещё не
готовый документ: виден стол, поверхность имеет оптическую проекцию, а каналы
R/G/B расходятся всё сильнее по глубине. Попытка исправить такой кадр одной
гомографией выравнивает внешний прямоугольник, но не устраняет локальное
поканальное искажение.

Оригинальный минидрайвер для модели 6000 всегда получает аппаратные 300 dpi.
Режимы 150/200/600 dpi находятся выше в Windows pipeline; 600 dpi не создаёт
новых оптических деталей.

## Заводская оптическая карта

Исследованный файл:

- `SV600u-x64.dll` из ScanSnap Home 4.0.0;
- SHA-256 `ABEE6D6CD8EB43F2512BAD1B9FDA9164AFAB5FC886992C6F9B6EE01134568F4C`;
- таблица по RVA `0x128270`;
- размер `4700×6`, элементы `float32`.

Первые три столбца задают вертикальные координатные поправки R/G/B, следующие
три — горизонтальный шаг R/G/B. Зелёный вертикальный столбец равен нулю.
Оригинальное ядро переводит вертикаль в Q12 через усечение `float*4096`, а
горизонталь в Q19 через усечение `float*524288`. Горизонтальная выборка
центрирована относительно середины строки; каждый канал интерполируется
отдельно.

Декомпилированное ручное ядро использует для горизонтального Q19-аккумулятора
беззнаковый 32-битный тип. Это существенно: на строке шириной 5104 его значение
в последней четверти превышает `INT_MAX`, но не `UINT32_MAX`. Знаковая версия
Linux-порта переполнялась именно там, подставляла тёмные пиксели с
противоположного края и перекрывала ближний левый угол портретного A4. После
перехода на `uint32_t` проверочная карандашная `Z` в этом углу сохраняется во
всех Color/Gray/Lineart режимах.

В репозитории таблица хранится как первая строка и точные знаковые `int8`-дельты
между строками. Все наблюдавшиеся дельты помещаются в этот диапазон. Развёрнутая
Q12/Q19-таблица имеет SHA-256
`e54baa1b99c89de56b33ac78a5af7d2ce92fcd6717c75dd20c99aaf048c4e0b7`.
Генератор и проверочный Python-прототип находятся в
`tools/prototype_sv600_optical_correction.py`.

Первые 2781 скорректированных строк соответствуют перехваченной области
Windows A4/Auto. Для фиксированного A3 нужны все 3542 строки firmware-кадра;
таблица 4700 строк покрывает обе области.

## Fixed A3L/A4L/A5L

Живые результаты ScanSnap Home Excellent (600 dpi):

| Профиль | Windows output | Backend 300 dpi |
|---|---:|---:|
| A3L | 9922×7012 | 4961×3506 |
| A4L | 7016×4958 до auto-rotation | 3508×2479 |
| A5L | 4962×3494 до auto-rotation | 2481×1747 |

Feature matching между перехваченным Windows boundary и A3 показал, что после
заводской поканальной карты в общей области остаётся практически только
трансляция, а не нелинейное растяжение по глубине. Поэтому fixed pipeline после
optical remap выполняет прямой crop без повторного resampling:

```text
corrected firmware field 5104×3542
  -> A3 plane: x=71, y=36, 4961×3506
  -> A4: x=823, y=77, 3508×2479
  -> A5: x=1336, y=77, 2481×1747
  -> optional whole-pixel rotation
```

Координаты A4 получены из прямого feature matching одной пары Windows boundary
и final: `x=1179, y=77`. Полезное поле Linux 5104 px расположено по центру
Windows boundary шириной 5816 px, поэтому локальный X равен
`1179-(5816-5104)/2=823`. A5 использует тот же сдвиг 25 px относительно
центрированного прямоугольника.

Это заменило раннюю ошибочную попытку продолжить A4 projective transform на
всю глубину A3. Та попытка меняла масштаб текста сверху вниз и в итоговый код
не входит.

Fixed profile не распознаёт смысл содержимого и не сжимает результат до
найденного контура. После crop A4/A5 backend закрашивает только область от
внешней рамки до первой устойчивой полосы светлой бумаги. Это убирает тёмный
стол без потери пикселей листа и не способно пройти через белый зазор к
карандашной пометке. Если край второй страницы внутри fixed-прямоугольника не
является внешним тёмным фоном, он остаётся в результате.

## Auto и режимы цвета

`Automatic detection (A4/Letter landscape)` использует первые 2781 строки
скорректированного поля, находит четыре угла, приводит лист к A4 и минимально
убирает связанный с внешней границей тёмный стол. В обычном SANE GUI этот режим
назначен рамке Letter/значению по умолчанию; явные A3/A4/A5 выбирают fixed crop.

Сканер аппаратно снимает Color. Gray формируется как настоящий SANE RGB8->Gray8,
Lineart — как RGB8->1 bit после всей геометрии. Нечётная ширина fixed output для
Lineart уменьшается максимум на семь правых пикселей, чтобы каждая строка
занимала целое число байтов и generic SANE downsampling завершался корректно.

## Штатная укладка

Для A3/A4/A5 производитель указывает только landscape (`A3L`, `A4L`, `A5L`):
лист лежит лицом вверх, длинной стороной параллельно основанию и центрируется по
метке. Портретный A4 почти полностью занимает глубину 300 мм и помещает дальний
край в худшую часть оптики; поэтому лучший исходный материал получается при
поперечной укладке и последующем повороте готовых пикселей.

Оригинальный матовый Background Pad повышает надёжность Auto. Fixed crop от него
не зависит; тёмная внешняя область A4/A5 закрашивается без изменения размера.
Книжная коррекция, разделение разворота, удаление пальцев, ручные контрольные
точки и page-turn намеренно не реализованы.
